# Historical baseline CodeQL local-input triage

This document records the original 64-alert baseline. The final independent [security review](SECURITY_EXPERT_REVIEW.md) covers all 78 reported candidates, including 14 subsequent findings, and governs the conditional per-alert approvals.

Reviewed 7 November 2026 by source and SARIF data-flow inspection. The expanded local-input setup reported 64 candidates against commit `4904f2e`; relevant current paths were compared with `b8f20e6`. Raw severity labels are query labels, not confirmed vulnerability severity. Each decision below applies to the reported source-to-sink flow, not every future use of that file or API.

There are 39 test-only flows (including three test-origin flows terminating in production helpers), 21 intended application-path flows, one allowlisted runtime-path flow, and three trusted build-toolchain flows. No attacker-controlled application-input path injection or command execution was established. Review dispositions are retained individually in GitHub; queries and languages remain enabled, with no blanket test exclusion.

The release operator must trust the checkout, compiler, SDK, environment and PATH. Selecting an executable deliberately is not sandboxed by argument-list execution or version checking. Likewise, the store constructor's root is a trusted caller capability; Path.GetFullPath alone is not a hostile-path sanitizer. Production supplies the current user's application directory. These decisions do not claim immunity from filesystem races by an attacker already controlling the same user's storage.

The separate WPF clipboard allocation race and signing/manual acceptance limits remain in [the open-source review](OPEN_SOURCE_REVIEW.md).
